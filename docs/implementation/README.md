## 文档使用说明

### 阅读顺序建议
- **新加入项目**: 按序号顺序阅读，先了解架构基础（09 数据层 → 10 依赖注入 → 07 文件系统 → 08 导航），再阅读具体功能模块
- **修改特定功能**: 直接定位到对应文档，查看"关键文件"和"如何工作"两节
- **添加新功能**: 参考相关功能文档的实现模式，遵循相同的架构规范

### 维护约束
- **修改功能前**：必须先阅读对应的功能点实现文档
- **修改/添加功能后**：必须同步更新或新增功能点实现文档
- **保持一致性**：文档中的代码引用（文件路径、类名、函数名）必须与实际代码匹配
- **文档格式**：所有文档使用 Markdown 格式，遵循现有文档的结构模板

### 文档模板
每个功能点文档应包含以下内容：
1. **功能概述** — 一句话描述
2. **关键文件** — 涉及的源文件路径列表
3. **核心类/函数** — 主要类和函数的简要说明
4. **设计架构** — 架构图和分层描述
5. **数据流** — 数据如何在各层之间流转
6. **关键实现细节** — 重要的实现逻辑和注意事项
7. **已知问题/技术债务** — 当前存在的问题
