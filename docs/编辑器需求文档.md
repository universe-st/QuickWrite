# QuickWrite 编辑器需求文档

## 1. 概述

编辑器是 QuickWrite 的核心创作模块，提供 Markdown 章节编辑、章节列表管理、自动保存等功能。编辑器位于"写作工作台"的"编辑"Tab 中，与"对话"Tab（AI 写作助手）同屏切换。

### 1.1 技术栈
- **编辑组件**: `markor-editor` 模块（基于 Markor HighlightingEditor 移植）
- **UI 框架**: Jetpack Compose + Material Design 3
- **架构**: MVVM（WritingViewModel）
- **文件格式**: Markdown + YAML Front Matter
- **存储**: 文件系统（`正文/` 目录下的 `.md` 文件）

### 1.2 整体布局

```

│  顶部栏: 项目标题 + 字数 + [保存] [≡/✕]    │

├────────────────────────────────────────────┤
│  ┌─ 章节列表 ────┐ ┌─ 编辑器 ────────────┐│

│  │───────────────│ │  # 第一章             ││
```

## 3. 章节管理

### 3.1 章节列表（左侧面板）

#### 3.1.1 面板结构
- **标题栏**: "章节"标签 + `[+]` 新建按钮
- **分隔线**
- **章节列表**（`LazyColumn`）：
  - 每个项目包含：上移/下移按钮 | 章节标题 | 分卷信息 | 摘要 | 删除按钮
  - 当前选中章节高亮（`primaryContainer` 背景）
  - 列表下方显示章节总数
- **分隔线**
- **尾部**: "N 章" 统计

> **设计**: 面板宽度固定 220dp，可通过顶部栏 `[≡/✕]` 按钮显示/隐藏，隐藏时使用 `AnimatedVisibility` + `slideInHorizontally/slideOutHorizontally` 动画。

#### 3.1.2 章节模型

```kotlin
data class ChapterFileInfo(
    val fileName: String,    // 文件名（含扩展名）
    val title: String,       // 章节标题（来自 YAML 或文件名）
    val order: Int,          // 排序序号
    val volume: String,      // 分卷信息
    val summary: String,     // 内容摘要
    val filePath: String     // 完整文件路径
)
```

#### 3.1.3 列表交互
| 操作 | 行为 |
|------|------|
| 点击章节 | 切换到该章节（自动保存当前章节） |
| 上移/下移 | 交换两个文件的 `order` 值实现排序 |
| 删除 | 删除文件并重新加载列表 |
| `[+]` | 弹出新建章节对话框 |
| 无章节时 | 显示"暂无章节"+"创建第一章"按钮 |

### 3.2 章节创建

#### 3.2.1 创建流程
1. 弹出 `AlertDialog`，输入章节标题
2. 标题非空时调用 `createNewChapter(title)`
3. ViewModel：
   - 保存当前章节
   - 使用标题作为文件名（`{title}.md`）
   - 生成新 `order`（当前最大 order + 1）
   - 写入初始内容（`# {title}\n\n`）
   - 重新加载章节列表

#### 3.2.2 新建章节对话框
```kotlin
AlertDialog(
    title = "新建章节",
    text = OutlinedTextField(placeholder = "章节标题"),
    confirmButton = "创建",
    dismissButton = "取消"
)
```

### 3.3 章节删除

#### 3.3.1 删除流程
1. 点击章节右侧 `[✕]` 按钮
2. ViewModel：
   - 通过 `ProjectManagementUseCase.deleteChapterFile()` 删除文件
   - 重新加载章节列表

> 当前为直接删除，未来可考虑添加二次确认。

### 3.4 章节排序

#### 3.4.1 排序机制
- 每个 `.md` 文件头部的 YAML Front Matter 中包含 `order` 字段
- 上移：`fromIndex--`，下移：`fromIndex++`
- ViewModel 读取两个章节的文件内容，交换 `order` 值，写回文件
- 章节列表始终按 `order` 升序排列

```kotlin
// 排序示例：将章节 A(order=2) 与 章节 B(order=1) 互换
// 1. 读取 A 内容，提取 body，构建新 meta(order=1)，写回
// 2. 读取 B 内容，提取 body，构建新 meta(order=2)，写回
// 3. 重新加载章节列表
```

> 排序操作不修改文件名，只交换文件中的 order 元数据。

## 4. 编辑器

### 4.1 核心组件

#### 4.1.1 MarkorEditor（`markor-editor` 模块）
基于 `HighlightingEditor`（继承 `AppCompatEditText`）的 Compose 封装。

**Composable 签名**:
```kotlin
@Composable
fun MarkorEditor(
    value: String,
    onValueChange: (String) -> Unit,
    modifier: Modifier = Modifier,
    editorConfig: EditorConfig = DefaultEditorConfig(),
    highlightingMode: HighlightingMode = HighlightingMode.PLAINTEXT,
    enabled: Boolean = true
)
```

**高亮模式**:
| 模式 | 值 | 说明 |
|------|-----|------|
| `PLAINTEXT` | `0` | 纯文本高亮 |
| `MARKDOWN` | `1` | Markdown 语法高亮（标题、列表、代码块等） |

#### 4.1.2 编辑器配置（`EditorConfig` 接口）

```kotlin
interface EditorConfig {
    fun isSpellingRedUnderlineEnabled(): Boolean = false
    fun isDarkModeEnabled(): Boolean = false
    fun getFontFamily(): String = ""
    fun getEditorForegroundColor(): Int = Color.BLACK
    fun getTabWidth(): Int = 4
    fun isDebugEnabled(): Boolean = false
}
```

**实现类 `AppEditorConfig`**:
```kotlin
class AppEditorConfig(
    private val isDark: Boolean,
    private val fontFamily: String = "",
    private val fontSizeSp: Int = 14
) : EditorConfig {
    override fun isDarkModeEnabled(): Boolean = isDark
    override fun getFontFamily(): String = fontFamily
    override fun getEditorForegroundColor(): Int =
        if (isDark) Color.WHITE else Color.BLACK
}
```

### 4.2 编辑器布局

编辑器区域位于 `Row` 中，包含：
1. **章节列表面板**（可选，220dp 宽）
2. **`VerticalDivider`**（分隔线，面板显示时可见）
3. **MarkorEditor**（占据剩余空间）

```kotlin
Row(modifier = Modifier.fillMaxSize()) {
    // 章节列表（AnimatedVisibility 控制显示/隐藏）
    AnimatedVisibility(visible = showChapterList) {
        ChapterListPanel(modifier = Modifier.width(220.dp).fillMaxHeight())
    }
    if (showChapterList) VerticalDivider()
    // 编辑器（key(currentChapterIndex) 强制重建）
    if (currentChapterIndex >= 0) {
        key(currentChapterIndex) {
            MarkorEditor(...)
        }
    }
}
```

> `key(currentChapterIndex)` 保证切换章节时重建编辑器实例，避免 TextWatcher 闭包捕获旧值。

### 4.3 编辑器行为

#### 4.3.1 内容加载
1. ViewModel 读取章节文件（`.md`）
2. `ChapterFileHelper.parseChapterContent()` 解析 YAML Front Matter 和正文
3. 将正文传入 `MarkorEditor.value`，元数据存入 `currentChapterMeta`
4. 编辑器显示纯正文内容，不显示 YAML Front Matter

#### 4.3.2 内容编辑
- 用户输入直接修改 `MarkorEditor` 的 `Editable`
- `TextWatcher.afterTextChanged()` 回调 `onValueChange`，更新 ViewModel 的 `editorContent`
- 实时计算字数

#### 4.3.3 内容保存
**触发时机**:
| 时机 | 说明 |
|------|------|
| 手动保存 | 点击顶部栏 `[保存]` 按钮 |
| 切换章节 | `selectChapter()` 先保存当前章节 |
| 创建新章节 | 新建前保存当前章节 |

**保存流程**:
1. ViewModel 检查 `isDirty` 标记
2. 调用 `ChapterFileHelper.buildChapterContent(meta, body)` 重组 YAML + 正文
3. 调用 `ProjectManagementUseCase.writeFileContent()` 写入文件
4. 更新项目统计信息
5. 显示"已保存"提示（2 秒后自动消失）

**保存状态指示**:
- 已保存：无文字或显示"已保存"（绿色提示）
- 未保存 (`isDirty = true`)：无特殊指示，`isDirty` 用于判断是否需要保存
- 保存中：`CircularProgressIndicator`（24dp，白色）
- 保存失败：显示"保存失败"（红色提示，2 秒后消失）

## 5. 章节文件格式

### 5.1 YAML Front Matter 格式

每个章节 `.md` 文件使用标准 YAML Front Matter 格式：

```markdown
---
title: "第一章：初入异世"
order: 1
volume: "第一卷：风云初起"
summary: "主角醒来发现自己穿越到了异世界"
---

# 第一章：初入异世

（正文内容...）
```

### 5.2 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `title` | String | 是 | 章节标题，显示在章节列表中 |
| `order` | Int | 是 | 排序序号，用于章节排序 |
| `volume` | String | 否 | 分卷信息，显示在章节列表的次要文本 |
| `summary` | String | 否 | 内容摘要，显示在章节列表的第三行 |

### 5.3 工具类 `ChapterFileHelper`

```kotlin
object ChapterFileHelper {
    // 解析文件内容 → (元数据, 正文)
    fun parseChapterContent(content: String): Pair<ChapterMeta, String>
    
    // 构建文件内容（元数据 + 正文）
    fun buildChapterContent(meta: ChapterMeta, body: String): String
    
    // 从正文提取标题（# 后的文字）
    fun extractTitleFromBody(body: String): String
}

data class ChapterMeta(
    val title: String = "",
    val order: Int = 0,
    val volume: String = "",
    val summary: String = ""
)
```

### 5.4 编辑约束

| 操作 | 行为 |
|------|------|
| 加载文件 | 自动剥离 YAML Front Matter，只传入正文 |
| 保存文件 | 自动重组 YAML Front Matter + 正文写入 |
| 编辑器内 | 不可编辑 YAML Front Matter |
| 切换章节 | 先保存当前章节再加载新章节 |

### 5.5 文件名约定
- 使用章节标题作为文件名：`{title}.md`
- 新章节标题为空时使用"未命名章节"

## 6. 字数统计

### 6.1 统计规则

```kotlin
fun countWords(text: String): Int {
    if (text.isBlank()) return 0
    val chinese = text.count { c ->
        c in '\u4E00'..'\u9FFF' ||
        c in '\u3000'..'\u303F' ||
        c in '\uFF00'..'\uFFEF'
    }
    val english = text.split(Regex("[\\s\\n]+"))
        .count { word ->
            word.any { c -> c in 'a'..'z' || c in 'A'..'Z' }
        }
    return chinese + english
}
```

- 中文汉字（CJK 统一表意文字区、标点区、全角区）每个计 1 字
- 英文按空格/换行分隔的单词计数
- 不统计 Markdown 标记符号和 YAML Front Matter

### 6.2 显示位置
| 位置 | 内容 |
|------|------|
| 顶部栏副标题 | `{字数}字` |
| 底部状态栏 | `第 {current}/{total}章 · 字数 {count}` |

## 9. 数据流

### 9.1 核心数据流

```
用户输入 → MarkorEditor.onValueChange → ViewModel.updateEditorContent()
  → editorContent 更新 → 字数重新计算 → isDirty = true
  → MarkorEditor.update{} 同步编辑器内容（防止外部覆盖）

用户保存 → ViewModel.saveCurrentChapter()
  → buildChapterContent(meta, body) → writeFileContent(filePath, content)
  → updateProjectStatistics() → isDirty = false

切换章节 → ViewModel.selectChapter(index)
  → saveCurrentChapter() → selectChapterInternal()
  → readFileContent() → parseChapterContent() → 更新 editorContent
```

### 9.2 ViewModel 关键方法

| 方法 | 说明 |
|------|------|
| `loadCurrentProject()` | 初始化加载主项目 |
| `selectChapter(index)` | 切换章节（先保存当前） |
| `updateEditorContent(text)` | 更新编辑器内容 |
| `saveCurrentChapter()` | 保存当前章节 |
| `createNewChapter(title)` | 创建新章节 |
| `deleteChapter(index)` | 删除章节 |
| `moveChapter(from, to)` | 移动章节位置 |
| `setSelectedTab(tab)` | 切换 Tab |

## 12. 已知限制与下次迭代

| 限制 | 说明 | 计划 |
|------|------|------|
| 无撤销/重做 | 当前 `MarkorEditor` 未暴露 undo/redo API | 未来版本 |
| 无自动保存定时器 | 仅在切换章节/创建章节时自动保存 | 未来按设置间隔自动保存 |
| 删除无确认 | 直接删除章节文件 | 添加确认对话框 |
| 章节目录展开/折叠 | 不支持多卷分组 | 未来可添加卷管理 |
| 章节模板选择 | 创建时只有空白模板 | 未来添加开端/发展/高潮/结局模板 |
| 编辑器字号/字体 | 硬编码 14sp，未从用户设置读取 | 通过 SettingsUseCase 读取 |
| 拖拽排序 | 目前只有按钮上下移动 | 未来支持拖拽手势 |
