# QuickWrite AI 对话系统需求文档

## 1. 功能概述

AI 对话系统是 QuickWrite 的写作辅助核心模块，允许用户在写作工作台"对话"Tab 中与 AI 进行多轮对话。系统采用 **Android Service 集中管理所有会话逻辑** 的架构，UI 层仅负责展示和交互，所有上下文维护、消息管理、API 调用和 Tool 执行均在 Service 中完成。

### 1.1 核心特性

- **多会话并行**：支持同时进行多个独立对话，每个会话维持独立的上下文
- **Service 驱动**：对话逻辑完全在 Android Service 中运行，界面销毁/重建不中断对话
- **自动标题生成**：会话中首次用户请求后，静默发送标题生成请求
- **Function Calling**：向 AI 模型提供 Tool 集，使其可主动操作项目文件系统
- **流式响应**：支持 SSE (Server-Sent Events) 流式解析，逐 token 显示回复

### 1.2 在系统架构中的位置

```
┌──────────────────────────────────────────────┐
│  UI Layer (Compose)                          │
│  ChatTab -> AiChatViewModel -> Service 绑定   │
│  仅负责：消息展示、输入交互、会话切换            │
├──────────────────────────────────────────────┤
│  AIChatService (Foreground Service)          │
│  负责：会话管理、消息流、API 调用、Tool 执行    │
│  独立于 Activity 生命周期                      │
├──────────────────────────────────────────────┤
│  Data Layer                                  │
│  AiApiService (Retrofit)  +  Room 持久化       │
└──────────────────────────────────────────────┘
```

## 2. Service 架构设计

### 2.1 AIChatService 核心职责

`AIChatService` 是一个 Android Foreground Service，承载所有对话核心逻辑：

| 职责 | 说明 |
|------|------|
| 会话生命周期管理 | 创建/销毁/切换会话 |
| 上下文维护 | 每个会话的消息历史、系统提示词 |
| API 请求发送 | 调用 OpenAI 兼容 API |
| 流式响应解析 | SSE 流解析，逐 token 推送 |
| Tool 调度与执行 | AI 模型调用的 Tool → 本地执行 → 结果回传 |
| 自动标题生成 | 首次消息后生题 |
| 持久化同步 | 消息写入 Room 数据库 |

**Service 不应负责的事项**：
- UI 渲染（由 Compose 负责）
- 文本编辑（在编辑 Tab 中完成）
- 项目文件创建/修改 → 通过 Tool 机制委托给 FileManager/Repository

### 2.2 与 UI 的通信机制

使用 **Binder + StateFlow** 双向通信：

```
┌─────────────────┐         Binder IPC         ┌─────────────────┐
│   Compose UI    │ ◄──────────────────────────► │  AIChatService  │
│ AiChatViewModel │  - bindService()             │                 │
│                 │  - ServiceConnection          │  SessionManager │
│                 │  - StateFlow 订阅             │  ApiDispatcher  │
│                 │  - 方法调用（send/stop/switch）│  ToolExecutor   │
└─────────────────┘                             └─────────────────┘
```

**Service 暴露的 Binder 接口** (`IChatService`)：


### 2.3 会话上下文结构

每个会话维护以下上下文信息，在每次 API 请求时组装为 messages 数组发送：

```kotlin
data class SessionContext(
    val sessionId: String,
    val projectId: String,
    val title: String,                    // 会话标题（自动生成或用户重命名）
    val systemPrompt: String,             // 系统提示词
    val modelConfigId: Int,               // 使用的 AI 模型配置 ID
    val messages: List<ChatMessage>,      // 完整消息历史
    val createdAt: Long,
    val updatedAt: Long,
    val isGenerating: Boolean             // 是否正在接收流式响应
)

data class ChatMessage(
    val id: Long,
    val role: MessageRole,               // system / user / assistant / tool
    val content: String,
    val tokenCount: Int = 0,
    val toolCalls: List<ToolCall>? = null,  // assistant 可能发起 tool call
    val toolCallId: String? = null,         // tool 消息关联的 call id
    val timestamp: Long
)

enum class MessageRole { SYSTEM, USER, ASSISTANT, TOOL }
```

**上下文组装策略**（每次 API 请求时）：
1. 第一条消息：`system` — 系统提示词
2. 后续消息：按时间顺序排列的 `user` / `assistant` / `tool` 消息
3. Token 总量超过模型上下文窗口时，从最早的消息开始截断（保留 system prompt 和最近的 N 条消息）

## 3. 会话管理

### 3.1 多会话并行

`SessionManager` 是 Service 内部组件，管理所有活跃会话：

```kotlin
class SessionManager(
    private val conversationRepository: AiConversationRepository,
    private val apiDispatcher: ApiDispatcher,
    private val toolExecutor: ToolExecutor
) {
    // 内存中的活跃会话映射
    private val activeSessions: MutableMap<String, SessionContext> = ConcurrentHashMap()
    
    // 每个会话的流式状态
    private val sessionStates: MutableMap<String, MutableStateFlow<SessionState>> = ConcurrentHashMap()
    
    fun createSession(...): String { }
    fun sendMessage(sessionId: String, content: String) { }
    fun stopGeneration(sessionId: String) { }
    fun switchSession(sessionId: String) { }
    // ...
}
```

**并行策略**：
- 每个会话有独立的 `CoroutineScope`，互不干扰
- API 请求使用独立的 OkHttp Dispatcher，不同会话可并行发起请求
- 同一会话内的消息串行处理（上一条回复完才能发下一条）
- 正在生成回复的会话可调用 `stopGeneration()` 中断

### 3.2 自动标题生成

**触发时机**：会话中首次用户消息发送后，AI 返回第一条回复时。

**流程**：
1. 用户发送第一条消息，AI 正常生成回复
2. 回复完成后，SessionManager 检测到这是该会话的第一条回复（`messages` 中此前只有 1 条 user 消息）
3. 自动构建静默请求：`"请用不超过10个字为以上对话生成一个标题，只输出标题文本，不要包含引号或任何解释。"`
4. 该请求不追加到 UI 消息列表中（标记 `silent = true`），仅将返回结果设置为会话标题
5. 标题更新通过 `sessionStates` StateFlow 推送到 UI

**静默消息标记**：

```kotlin
data class ChatMessage(
    // ...
    val silent: Boolean = false   // 静默消息不显示在 UI 中
)
```

**标题生成失败处理**：使用截断的用户消息首行作为默认标题（如 `"帮我写一段..."`）。

### 3.3 会话持久化

会话和消息同步写入 Room 数据库，支持应用重启后恢复：

| 表 | 存储内容 |
|----|---------|
| `ai_sessions` | 会话元数据（标题、项目ID、模型配置、创建时间） |
| `ai_messages` | 消息记录（角色、内容、token数、静默标记） |

**持久化时机**：
- 会话创建时：写入 `ai_sessions`
- 用户消息发送时：立即写入 `ai_messages`
- AI 回复完整接收时：写入 `ai_messages`
- 流式中间 token：仅内存，不写入数据库
- 标题生成完成时：更新 `ai_sessions.title`

### 3.4 会话状态定义

```kotlin
sealed class SessionState {
    object Idle : SessionState()                                    // 空闲，等待用户输入
    data class Generating(val partialContent: String) : SessionState()  // AI 正在生成
    data class Error(val message: UiText) : SessionState()             // 出错
}

data class SessionSummary(
    val sessionId: String,
    val title: String,
    val lastMessage: String,          // 最后一条消息摘要
    val messageCount: Int,
    val createdAt: Long,
    val updatedAt: Long,
    val isActive: Boolean             // 是否有正在进行的生成
)
```

## 5. Function Calling — AI 工具集

### 5.1 工具架构

Service 中的 `ToolExecutor` 负责注册和执行工具。工具定义遵循 OpenAI Function Calling 规范，在每次 API 请求的 `tools` 参数中声明。

```kotlin
interface ChatTool {
    /** 工具定义（符合 OpenAI function schema） */
    val definition: ToolDefinition
    
    /** 执行工具调用，返回结果文本 */
    suspend fun execute(arguments: JSONObject, context: ToolContext): String
}

data class ToolDefinition(
    val name: String,
    val description: String,
    val parameters: JSONObject   // JSON Schema 格式的参数定义
)

data class ToolContext(
    val projectId: String,
    val fileManager: FileManager,
    val projectRepository: ProjectRepository,
    val projectManagementUseCase: ProjectManagementUseCase
)
```

| **限制** | 仅允许修改指定字段，不允许修改 id、createdTime、storagePath 等 |

#### T12. `create_project` — 创建项目

| 属性 | 值 |
|------|-----|
| **名称** | `create_project` |
| **描述** | 创建新的小说项目，自动生成目录结构和元数据文件 |
| **参数** | `title: string` — 小说标题；`author: string` — 作者名；`genre: string` — 小说类型；`description: string` (可选) — 项目描述 |
| **执行** | 调用 `ProjectManagementUseCase.createProject()`，生成 UUID、创建目录结构、写入 info.json、插入 Room 记录 |
| **返回** | JSON，含 created、projectId、title、storagePath |

#### T13. `delete_project` — 删除项目

| 属性 | 值 |
|------|-----|
| **名称** | `delete_project` |
| **描述** | 删除指定项目，包括数据库记录和所有文件 |
| **参数** | `projectId: string` — 项目 ID；`confirmTitle: string` — 必须提供项目标题以确认删除 |
| **执行** | 验证 confirmTitle 与项目标题匹配 → 调用 `ProjectManagementUseCase.deleteProject()` |
| **安全** | 双重验证，防止误删；confirmTitle 不匹配则拒绝并返回错误 |
| **返回** | JSON，含 deleted、projectId、title |

### 5.3 Tool Call 执行流程

```
用户消息
    │
    ▼
┌──────────────────────────────────────┐
│  发送到 AI API（含 tools 定义 + 上下文）│
└──────────────┬───────────────────────┘
               │
               ▼
┌──────────────────────────┐    是     ┌─────────────────┐
│ 响应包含 tool_calls？     │─────────► │ ToolExecutor    │
└──────────┬───────────────┘           │ 逐个执行 tool    │
           │ 否                         │ 收集结果         │
           ▼                            └────────┬────────┘
┌──────────────────────────┐                    │
│ 直接返回文本内容           │                    ▼
│ 推送到 UI                 │           ┌──────────────────┐
└──────────────────────────┘           │ 将 tool 结果作为    │
                                       │ tool role 消息     │
                                       │ 追加到上下文       │
                                       │ 再次发送到 AI API  │
                                       └────────┬──────────┘
                                                │
                                                ▼
                                       ┌──────────────────┐
                                       │ 继续循环直到       │
                                       │ AI 返回最终文本    │
                                       └──────────────────┘
```

**Tool Call 循环终止条件**：
- AI 返回不包含 `tool_calls` 的文本响应 → 正常结束
- 循环超过 10 轮 → 强制终止并返回错误
- 用户调用 `stopGeneration()` → 中断

**Tool 结果消息**：每个 Tool Call 结果以 `role: "tool"` 消息追加到上下文中，`tool_call_id` 关联到对应的 Assistant tool call。

### 5.4 操作抽象与回溯机制

所有 AI 通过 Tool 执行的修改性操作统一抽象为 `AiOperation`，支持可回溯判断和状态恢复。

#### 5.4.1 操作抽象基类

```kotlin
/**
 * AI 操作抽象基类
 * 所有会修改项目状态的 Tool 执行都封装为此类的子类实例
 */
sealed class AiOperation {
    abstract val id: String                          // 操作唯一 ID (UUID)
    abstract val type: OperationType                 // 操作类型
    abstract val projectId: String                   // 所属项目
    abstract val sessionId: String                   // 所属会话
    abstract val toolCallId: String                  // 关联的 Tool Call ID
    abstract val executedAt: Long                    // 执行时间

    /**
     * 判断当前是否可以回溯此操作
     * 返回 null 表示可以回溯，返回非 null 字符串表示不可回溯的原因
     */
    abstract suspend fun canRollback(context: ToolContext): String?

    /**
     * 执行回溯操作，将项目状态恢复到操作前的状态
     * 调用前应先通过 canRollback() 检查
     */
    abstract suspend fun rollback(context: ToolContext): Result<Unit>
}

enum class OperationType {
    EDIT_FILE,       // 编辑文件
    DELETE_FILE,     // 删除文件
    CREATE_FILE,     // 创建文件
    MOVE_FILE,       // 移动文件
    COPY_FILE,       // 复制文件
    CREATE_PROJECT,  // 创建项目
    DELETE_PROJECT,  // 删除项目
    UPDATE_PROJECT   // 修改项目信息
}
```

#### 5.4.2 可回溯判断规则

每种操作类型有独立的可回溯判断逻辑：

| 操作类型 | 可回溯条件 | 不可回溯原因示例 |
|---------|-----------|----------------|
| `EDIT_FILE` | 备份文件存在 **且** 当前文件的 SHA-256 哈希值 == 编辑后记录的哈希值 | "文件已被用户修改，哈希值不匹配"；"备份文件不存在" |
| `DELETE_FILE` | 备份文件存在 | "备份文件不存在" |
| `CREATE_FILE` | 创建的文件仍存在 | "文件已被手动删除" |
| `MOVE_FILE` | 目标路径文件/目录存在 **且** 内容哈希与移动时一致；源路径未产生新文件/目录 | "目标文件已被修改"；"源路径已被新文件占用" |
| `COPY_FILE` | 目标路径文件存在 **且** 内容哈希与复制时一致 | "目标文件已被修改"；"目标文件不存在" |
| `CREATE_PROJECT` | 项目数据库中仍存在 **且** storagePath 目录存在 | "项目已被删除" |
| `DELETE_PROJECT` | 项目备份目录存在 **且** 当前无同名项目记录 | "同名项目已重新创建" |
| `UPDATE_PROJECT` | 项目的数据库记录字段值 == 操作后记录的值（逐字段哈希对比） | "项目信息已被修改" |

#### 5.4.3 各操作的回溯实现

**EDIT_FILE 回溯**：

```kotlin
data class EditFileOperation(
    override val id: String,
    override val projectId: String,
    override val sessionId: String,
    override val toolCallId: String,
    override val executedAt: Long,
    val filePath: String,               // 编辑文件的相对路径
    val hashAfterEdit: String,          // 编辑后文件的 SHA-256 哈希
    val hashBeforeEdit: String,         // 编辑前文件的 SHA-256 哈希
    val lastModifiedAfterEdit: Long     // 编辑后的 lastModified 时间
) : AiOperation() {

    override val type = OperationType.EDIT_FILE

    override suspend fun canRollback(context: ToolContext): String? {
        val fullPath = File(context.fileManager.getProjectDirectory(projectId), filePath).absolutePath
        if (!context.fileManager.isPathSafe(fullPath)) return "路径不安全"

        val currentFile = File(fullPath)
        if (!currentFile.exists()) return "文件已不存在"

        val currentHash = computeSha256(currentFile)
        if (currentHash != hashAfterEdit) return "文件已被修改（哈希值不匹配），无法回溯"

        val backupFile = getBackupFile(id)
        if (!backupFile.exists()) return "备份文件不存在"

        return null // 可以回溯
    }

    override suspend fun rollback(context: ToolContext): Result<Unit> {
        val fullPath = File(context.fileManager.getProjectDirectory(projectId), filePath).absolutePath
        val backupFile = getBackupFile(id)
        return try {
            backupFile.copyTo(File(fullPath), overwrite = true)
            Result.success(Unit)
        } catch (e: Exception) {
            Result.failure(e)
        }
    }
}
```

**DELETE_FILE 回溯**：

```kotlin
data class DeleteFileOperation(
    override val id: String,
    override val projectId: String,
    override val sessionId: String,
    override val toolCallId: String,
    override val executedAt: Long,
    val filePath: String,               // 被删除文件的相对路径
    val deletedHash: String,            // 被删除文件的 SHA-256 哈希
    val isDirectory: Boolean            // 是否目录
) : AiOperation() {

    override val type = OperationType.DELETE_FILE

    override suspend fun canRollback(context: ToolContext): String? {
        val backupFile = getBackupFile(id)
        if (!backupFile.exists()) return "备份文件不存在"
        return null
    }

    override suspend fun rollback(context: ToolContext): Result<Unit> {
        val fullPath = File(context.fileManager.getProjectDirectory(projectId), filePath).absolutePath
        val backupFile = getBackupFile(id)
        return try {
            fullPath.let { File(it).parentFile?.mkdirs() }
            if (isDirectory) {
                // 从 ZIP 备份恢复目录
                context.fileManager.extractZipTo(backupFile, File(fullPath))
            } else {
                backupFile.copyTo(File(fullPath), overwrite = false)
            }
            Result.success(Unit)
        } catch (e: Exception) {
            Result.failure(e)
        }
    }
}
```

**备份大小限制**：

```kotlin
    private val maxTotalSize: Long = 5L * 1024 * 1024 * 1024  // 5 GB
) {
    suspend fun ensureCapacity(requiredSize: Long) {
        var totalSize = calculateTotalSize()
        while (totalSize + requiredSize > maxTotalSize) {
            val oldest = findOldestExpendableOperation()
            if (oldest == null) throw BackupCapacityExceededException()
            deleteBackup(oldest.id)
            totalSize = calculateTotalSize()
        }
    }

    suspend fun clearAll() {
        backupDir.deleteRecursively()
        backupDir.mkdirs()
    }

    fun getTotalBackupSize(): Long
    fun getBackupCount(): Int
}
```

#### 5.4.5 哈希计算

使用 SHA-256 计算文件内容哈希：

```kotlin
fun computeSha256(file: File): String {
    val digest = MessageDigest.getInstance("SHA-256")
    FileInputStream(file).use { fis ->
        val buffer = ByteArray(8192)
        var bytesRead: Int
        while (fis.read(buffer).also { bytesRead = it } != -1) {
            digest.update(buffer, 0, bytesRead)
        }
    }
    return digest.digest().joinToString("") { "%02x".format(it) }
}
```

哈希仅基于文件内容，不包含文件名、路径或元数据，确保跨移动/重命名后哈希仍然匹配。

## 10. 错误处理

### 10.1 网络错误

| 错误类型 | 处理策略 |
|---------|---------|
| 网络不可用 | 显示 Snackbar "网络不可用"，消息保留在输入框中不丢失 |
| 请求超时 | 自动重试 1 次，仍失败则显示错误；用户可手动重试 |
| API 返回 4xx | 显示具体错误信息（如 "API Key 无效"） |
| API 返回 5xx | 显示 "AI 服务暂时不可用，请稍后再试"，支持重试 |
| 流式中断 | 保留已接收的部分内容，显示 "连接中断"，提供重试按钮 |

### 10.2 Tool 执行错误

| 错误类型 | 返回给 AI 的内容 |
|---------|----------------|
| 路径不安全 | `Error: 路径不在项目范围内` |
| 文件不存在 | `Error: 文件不存在: {path}` |
| 权限不足 | `Error: 无权限操作此文件` |
| 执行异常 | `Error: 操作失败: {exception message}` |

Tool 执行错误不阻断对话，将错误信息作为 tool 结果返回给 AI，由 AI 决定下一步操作。

### 10.3 UI 错误状态

- 错误消息通过 Snackbar 显示
- 发送失败的消息保留在输入框中
- 重试按钮出现在失败消息气泡旁

## 11. 安全性考虑

- **路径安全**：所有文件操作前调用 `FileManager.isPathSafe()` 验证，防止目录遍历
- **项目隔离**：工具只能操作指定 projectId 的文件，不能跨项目访问
- **删除保护**：项目删除需确认标题；禁止删除核心目录
- **API Key 安全**：升级到加密存储（EncryptedSharedPreferences 或 Android Keystore）
- **输入验证**：所有用户输入和 AI 返回内容进行适当的清理
